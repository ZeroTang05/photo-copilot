# MVP 范围与交付门槛

## 首版价值

摄影爱好者可以用一句话表达修改方向，看到可调整的修图结果，并理解每次变化。产品通过参数、区域和可撤销操作建立控制感。

第一优先级为完成单张照片的完整编辑与导出。第二优先级为验证 AI 的建议质量和局部指令理解。第三优先级为解释是否帮助使用者接受或修正建议。

## 需要验证的假设

| 假设 | 实验 | 达标信号 |
| --- | --- | --- |
| AI 建议产生实际价值 | 15 位摄影爱好者各完成至少 3 张自选照片 | 至少 10 人独立完成导出，其中至少 8 人认为建议有帮助 |
| 参数可见性提高控制感 | 每人执行一次手动修正和一次撤销 | 至少 12 人无需指导完成 |
| 自然语言局部调整可用 | 30 条真实局部任务，由两名评审看区域与结果 | 至少 24 条意图及区域大致正确 |
| 模型能理解自有参数 | 60 张真实照片上的固定指令集 | 达到 VALIDATION 的 AI 门槛 |
| 成本适合继续迭代 | 统计真实 token 用量和调用次数 | 每张成功导出照片的 AI 平均成本不超过 0.10 美元 |

人数与成本是试验标准，样本不足时结论保持探索性。模型质量未达标时先调整参数说明与提示词，再决定模型替换。不得通过自动循环调用掩盖首轮成功率。

## 必须交付

| 编号 | 能力 | 首版深度 |
| --- | --- | --- |
| FR-01 | 图片导入 | 多张选择或拖入，支持 JPEG、PNG、WebP、AVIF、GIF、TIFF 与相机 RAW；逐张独立编辑 |
| FR-02 | 实时画布 | 适应窗口、百分之百查看、缩放和平移 |
| FR-03 | 基础参数 | 曝光、对比、高光、阴影、暖冷、色偏、饱和度 |
| FR-04 | 构图 | 自由裁切、固定比例、正负 180 度旋转与自动裁切 |
| FR-05 | AI 初次建议 | 一次调用生成观察、完整变更集和解释，先预览后应用 |
| FR-06 | 自然语言追问 | 基于当前状态产生绝对赋值变更集，支持全局和局部任务 |
| FR-07 | 局部区域 | 最多 4 个可移动、缩放和羽化的椭圆、线性渐变或画笔蒙版，局部曝光、高光和饱和度 |
| FR-08 | 解释 | 观察、修改意图、具体变化、局限说明与区域关联 |
| FR-09 | 编辑历史 | 撤销、重做、重置和同构图前后对比 |
| FR-10 | 图片导出 | 浏览器内 JPEG、PNG、WebP、AVIF 或 TIFF 导出，保留当前裁切与调色结果 |
| FR-11 | 请求控制 | 取消、错误反馈、过期结果丢弃和限额提示 |
| FR-12 | 隐私与可用性 | AI 发送说明、无邀请门槛(匿名会话 + 速率配额)、键盘操作和明确设备边界 |

MVP 必须实现 FR-01 至 FR-12。局部编辑属于核心闭环。椭圆表示一个柔和范围，界面支持显示和修正范围；精确对象边界识别另行立项。

## 文件与运行边界

导入文件上限为 100 MiB，像素上限为 1 亿，每边至少 64 像素，任一边上限为 16384 像素。GPU 能力还需满足实际图片纹理尺寸。图片超限时显示具体限制并保持现有照片。

预览长边上限为 2048 像素。AI 发送两张长边上限为 1024 像素的 JPEG，分别为规范化原图和当前参数效果图，二者都保留完整原图构图。AI 输入的二进制总大小上限为 1.5 MiB。

编辑画布保持导入图片的完整像素尺寸，不会为了发送 AI 而降低本地编辑和导出的分辨率。导入时图片会转换为 sRGB PNG，因此 EXIF 和原始色彩配置不会保留。JPEG、WebP 与 AVIF 是有损编码；PNG 与 TIFF 适合需要继续处理的高质量中间文件。AI 仅接收压缩预览图，不会接收完整分辨率的编辑画布。

浏览器通过能力检测后进入编辑器。首版承诺范围为实际验证过的桌面 Chrome 和 Edge。其他浏览器可尝试运行，支持状态需明示。缺少 WebGL2 或高精度片元计算能力时展示不可编辑状态。

## 后续范围

V1 考虑语义分割、曲线、HSL、项目保存和移动端适配。V2 根据需求证据评估批量同步编辑、个性化风格和商业化。

生成式补画、移除物体、换天空、磨皮、人像身份识别、多人协作、素材库、XMP 导出和 Lightroom 数值兼容均未纳入当前版本计划。高光控制改变已有像素的亮度分布，已经裁切成纯白的纹理无法通过该算法恢复。

## 放行标准

所有 FR 需求具备通过记录。真实 API 闭环完成，预览与导出的一致性达标。模型失败、取消和迟到响应均不会污染当前状态。导出文件可在浏览器与操作系统图片查看器打开。

试用运营需配备模型凭据、服务端每日用量限制(每匿名会话与全局两层)和明确的发送说明。开发完成和上线授权分开记录。公开上线需要另行确认发布范围。
