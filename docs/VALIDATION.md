# 验证与发布门槛

## 验证纪律

每个阶段完成目标后集中验证相关行为，发现问题后围绕失败项修复与复测。最终发布候选再执行完整矩阵。真实渲染、编码、网络与模型能力使用真实环境验证。

纯函数测试可以构造合法与非法输入，用于验证不变量。构造输入不替代真实图片、GPU 或 API。所有记录标明已执行、未执行、失败或受阻，禁止把测试计划写成通过结果。

## 当前验证状态

当前交付已进入 MVP 验证阶段。领域测试、生产构建和 Cloudflare 部署预检已经通过；真实浏览器已完成基础编辑流程检查。完整真实照片集、跨设备性能、模型质量和试用数据仍未完成，具体状态见 [MVP 实现与验证记录](evidence/MVP-IMPLEMENTATION.md)。

## 真实照片样本

采用 60 张拥有使用权限的照片，包含人像 15 张、风景 15 张、夜景 10 张、室内 10 张、复杂高光与色偏 10 张。每张记录来源授权、分辨率、主要困难和目标操作，真实人物照片取得适用的测试使用同意。

从中选择 20 张作为提示词开发集，40 张作为保留评测集。保留集在阶段评测前不用于提示词定向修改，报告分别展示两个集合的结果。

额外建立 EXIF 八方向、PNG 透明、带 ICC、损坏文件、超限文件与动画 PNG 样本。优先使用真实文件，几何角点图和渐变色阶图可程序生成用于验证数学性质。

## 行为矩阵

| 验证项 | 关联需求 | 必须覆盖的事实 |
| --- | --- | --- |
| 导入规范化 | FR-01 | EXIF 八方向正确、尺寸正确、ICC 路径明确、透明白底、损坏与超限不替换旧图 |
| 画布视口 | FR-02 | 适应窗口与百分之百查看正确、缩放平移不写历史、窗口改变后控制仍可访问 |
| 参数数学 | FR-03 | 零值近似恒等、正曝光单调、饱和度负 100 为灰度、参数越界被拒绝 |
| 局部区域 | FR-07 | 椭圆外无影响、羽化边缘连续、重叠可预测、区域顺序无影响 |
| 几何与坐标 | FR-04、FR-07 | 非方形图片旋转后区域跟随内容、裁切四角合法、正负角度一致 |
| 历史事务 | FR-09 | 一次拖动一个节点、撤销后新编辑清空重做、revision 单调递增 |
| AI 计划校验 | FR-05、FR-06 | 未涉及字段不变、绝对赋值、未知字段拒绝、非法计划原子失败 |
| 解释一致性 | FR-08 | 展示差值来自实际状态、理由指向真实操作、无虚构恢复细节 |
| 竞争时序 | FR-11 | 手动修改、换图、撤销后旧响应无效，重复应用无效 |
| 导出一致性 | FR-10 | 同尺寸像素误差达标、正确尺寸、无块接缝、所选格式可打开、无 GPS |
| 网络与配额 | FR-11、FR-12 | 无效 Origin 失败、额度计算包含修复、日志无图片 Base64、Cookie 与密钥 |
| 键盘与状态 | FR-12 | 焦点可见、中文名称完整、输入框撤销优先、AI 等待时本地编辑可用 |

参数数学和事务使用 Vitest。画布、文件和网络使用 Playwright 加真实浏览器。竞争测试通过控制响应释放顺序、明确事件屏障或真实测试网关的受控延迟实现，禁止依赖长时间休眠碰撞时序。

## AI 评估设计

每张评测照片执行一条 auto 指令和一条 followup 指令。至少 30 条 followup 包含局部区域任务。主报告采用首次有效请求结果，格式修复后的成功率单独统计。

两名评审分别查看原图、指令和结果，评定意图遵循、区域位置、自然度、主体保留与解释准确性。每项分为 1 至 5 分，发生显著分歧时记录讨论结论。自动清晰度或饱和度指标不能代替人工偏好判断。

| 指标 | 放行门槛 | 统计方式 |
| --- | --- | --- |
| 首轮 Schema 与业务有效率 | 至少百分之九十五 | 未修复有效结果除以全部模型请求 |
| 一次修复后的有效率 | 至少百分之九十九 | 含修复有效结果除以全部模型请求 |
| 意图遵循 | 至少百分之八十五达到 4 分 | 包括合理 clarify，单独展示其占比 |
| 局部目标与方向正确 | 至少百分之八十 | 30 条以上局部任务中的正确数 |
| 成片相对原图偏好 | 至少百分之六十 | 盲评偏好改善图的照片比例，平局单列 |
| 严重主体误伤 | 零个 | 裁掉主要人物、显著肤色损坏或大范围错误区域 |
| 非法或过期状态应用 | 零个 | 全部领域与端到端用例 |

百分比必须同时列出实际数量。小样本百分之九十九门槛可能等价于零失败，报告直接展示数量以免误读。

## 性能与兼容性

至少测试一台 Windows 16 GB 内存桌面机与另一台不同 GPU 的桌面设备。Chrome 和 Edge 均使用记录在报告中的正式版本，开启硬件加速。至少一次人工检查来自真实 GPU 的画布，CI 软件渲染结果不能替代。

| 项目 | 目标 | 测量方式 |
| --- | --- | --- |
| 导入首帧 | 第 95 百分位低于 3 秒 | 至少 20 次 1200 万与 2400 万像素照片导入 |
| 滑杆响应 | 第 95 百分位低于 50 毫秒 | 2048 预览、4 区域，输入事件到帧提交，结合浏览器性能记录核验 |
| 导出 | 第 95 百分位低于 15 秒 | 至少 20 次 2400 万像素或相应最大裁切输出 |
| AI 响应 | 第 50 百分位低于 10 秒，第 95 百分位低于 25 秒 | 至少 30 次真实请求，单独报告网络与修复 |
| GPU 资源 | 连续换图 20 次无资源持续增长趋势 | 观察纹理销毁、堆快照和上下文状态 |
| 渲染一致性 | 平均误差至多 1，第 99 百分位至多 3 | 相同尺寸、JPEG 编码前 RGBA 每通道差 |

浏览器无法直接观测最终屏幕显示时刻时，将帧提交延迟标为近似指标，补充人工交互检查，不把 requestAnimationFrame 时间当作精确显示完成时间。

验证 GPU 上下文丢失后能从仍在内存的规范化资源和 EditState 重建。重建失败时显示明确状态，禁止隐藏渲染错误或丢弃参数。

## 隐私与接口验证

通过真实网络抓取确认导入、滑杆、裁切和导出不会发送照片。首次 AI 同意之前无缩略图请求。AI 请求体仅包含规格允许的数据，两张 JPEG 均未包含 EXIF 和 GPS。

检查前端构建产物和网络响应不含服务端密钥。校验外域 Origin、无会话、重复 requestId、超限图片、未知字段和伪造区域 ID 的请求。检查运行日志字段：不含图片 Base64、Cookie 或凭据；模型输出 JSON 仅用于模型兼容性和失败诊断，并按部署平台的日志保留规则处理。

检查匿名会话的自动签发、cookie HMAC 校验、会话到期、每分钟和每日额度，以及第二次修复消耗额度的行为。确认进程重启清零的首版局限在运营记录中可见。

## 证据归档

开发阶段创建 docs/evidence，按阶段保存环境清单、用例结果、失败解释和批准使用的样本引用。真实照片及含人物的截图默认保留在受控本地目录，进入版本库前单独确认样本授权。

发布报告包含需求编号、对应测试、实际结果、模型与提示版本、设备、耗时与成本、剩余缺陷。未运行的真实 API 用例必须标明受阻原因。

发布候选必须实现全部 FR 需求，阻断级缺陷为零。严重主体误伤、密钥泄漏、错误计划应用、导出失败或明显预览差异均阻断发布。当前设计文档不构成部署授权。
