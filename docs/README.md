# Photo Copilot 项目文档

文档版本为 1.1，更新日期为 2026-09-22。MVP 的代码实现与 Vercel、Cloudflare 两种独立部署目标已经具备；真实模型稳定性、跨设备性能和试用数据仍在验证中。

## 产品结论

Photo Copilot 面向摄影爱好者，提供浏览器内的参数式修图。照片导入后，AI 提出构图、光线和色彩建议，画布展示效果，参数面板展示对应变化。使用者可以用自然语言继续指导，也可以直接拖动滑杆和局部区域。

核心闭环为导入照片、获取建议、预览与应用、局部追问、手动微调、导出图片。首版包含可解释的局部调整，覆盖太阳附近暗一点、画面左侧亮一点等需求。

推荐架构为浏览器图像引擎、确定性的编辑状态和轻量模型网关。原始文件留在浏览器，模型分析需要发送经过重新编码的缩略图。完全无服务器且由运营方提供模型密钥的路线无法满足密钥保密要求，因此采用轻量网关。纯离线模型和自带密钥模式留待后续评估。

## 文档权威边界

MVP 决定首版范围，PRD 决定可观察的产品行为，SPEC 决定数据与渲染语义，AI-WORKFLOW 决定网络契约。ARCHITECTURE 解释实现选择，ROADMAP 排定执行顺序，VALIDATION 定义验证证据。发现相互矛盾时先修正文档，再继续相关实现。

需求使用 FR 编号，技术决策使用 ADR 编号，交付任务使用 T 编号。开发交付需说明对应编号与验证记录。

## 设计假设

| 项目 | 本版采用的假设 | 影响 |
| --- | --- | --- |
| 产品阶段 | 开放验证 | 服务端使用匿名会话和速率配额(无邀请码门槛),无完整账户系统 |
| 目标设备 | 桌面 Chrome 和 Edge，视口宽度至少 1024 CSS 像素 | 移动端完整编辑体验进入后续阶段 |
| 发布环境 | 能合法访问所选模型服务的环境 | 公开发布前核验目标地区与服务可用性 |
| 团队 | 一名全栈开发配合开发模型，阶段性产品验收 | 时间为规划估算，按门槛推进 |
| 文件 | 多张照片导入并逐张独立编辑 | 支持常见图片、TIFF 与浏览器可解码的相机 RAW；不提供批量同步编辑 |
| 存储 | 当前标签页内存 | 刷新后需要重新导入，首版没有自动保存和备份 |
| 商业模式 | 免费限额开放试用 | 先测价值和成本，再决定订阅或点数 |

这些假设构成可执行默认方案。域名、托管账号、模型凭据、试用成员和公开上线地区在对应里程碑开始前补齐，不影响先开发本地图像引擎。

## 交给开发模型的工作指令

按阅读顺序读完文档，先执行 ROADMAP 的 G0 技术验证，再按 T 编号交付纵向功能。产品文案使用简体中文。所有参数遵循 SPEC 的自有算法语义，所有网络请求遵循 AI-WORKFLOW。模型只能产生候选计划，已提交状态由浏览器状态模块持有。

使用真实浏览器、真实图片和真实模型 API 验证关键闭环。凭据缺失时记录对应工作受阻，继续独立的本地图像任务。不得用固定回复冒充 AI 能力。测试构造的边界输入可以用于纯函数验证。

每个阶段完成目标后集中执行相关测试。开发模型应更新任务状态、已验证环境和剩余问题。不得扩展首版为通用图层编辑器、账户平台或多模型代理框架。代码提交、推送、发布和部署按后续明确授权执行。
